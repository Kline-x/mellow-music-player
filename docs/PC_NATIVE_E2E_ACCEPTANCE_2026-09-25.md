# PC 原生客户端用户视角 E2E 验收记录（2026-09-25）

> **本轮结论：部分验收，完整 E2E 尚未完成，不予放行。** 用户允许前台操作后，本轮将 macOS 原生 Mellow Music 窗口激活并获得真实新截图，切换多个页面、观察收藏/历史/本地库/歌单广场/排行榜/声音电台等用户可见状态。尝试通过系统级 pointer/keyboard 向 Flutter 窗口送入操作，但动作与页面切换/输入状态无法稳定对应（含搜索输入与队列）；因此不把未确认的点击当成功，也不把未操作项判通过。新截图+当前生产源码核实出首页/榜单/歌手/电台等多类硬编码指标与曲池（DATA-01），并确认播放队列与进度无冷启动恢复实现（DATA-02）。视觉和功能尚未全覆盖，不能以测试报告代替。

- **前台操作授权**：用户明确允许短暂激活原生客户端。本轮在首次取证后继续重新打开应用并尝试搜索/播放/队列；键鼠事件无法稳定命中控件。报告证据确认了导航视图与静态数据，不声称关键用户动作已完整验收；本轮结束前恢复 DSH 前台。

## 4. 数据验收

本轮启动首屏 OCR 读到展示 6 首默认队列（云水禅心、晚风告白、海阔天空、夜的第七章、City of Stars、起风了），Dock 显示云水禅心 / 巫娜 / 04:28 / 00:00。前台另页实测显示：播放历史 3 条（想你就写信 Live、云水禅心、告白气球 Live），收藏页显示 4 首，本地库 0 首/0 个目录，自建/外部歌单均 0 条。只读沙箱偏好 `~/Library/Containers/com.mellow.music.app/Data/Library/Preferences/com.mellow.music.app.plist`（2026-09-24 01:34:44）无收藏 ID/实体，也没有队列快照键；有旧进度键记录告白气球 Live，25088ms。生产 `AudioPlayerService._loadFromStorage()` 不读队列或位置，并以 `mockPresetTracks` 初始化队列。收藏页“4 首”与空持久化收藏冲突，源码又预置 4 个 ID，已作为 DATA-03 记录。偏好只读、未修改。

- **DATA-01｜首页/榜单/歌手/电台数值与个性化来源是假数据（P1，截图+源码核实）**：发现页截图实显「根据您常听的古风与经典流行智能漫游」与播放量 48.6/129.4/98.2/45.1 万。源码 `desktop_views.dart:73-75,156-180` 将画像、4 张卡片与播放量作为常量并绑定命名 mock 曲池，没有真实用户偏好或统计源。前台进入巅峰榜单后显示「每日09:00更新·100首」「每周四更新·200首」「全网官方权威与特色榜单（63）」；当前 `DesktopToplistView` 渲染榜单数量和更新文案为静态表项（源码 `desktop_views.dart:432-750`）。进入声音电台页显示 24.8/58.2/36.5/19.4 万在听；`track_model.dart:907,931,954,977` 中这些 listener 值都是常量。热门歌手页标题宣称「官方全量真实数据」，显示陈奕迅 29130 万粉丝、林俊杰 9396 万、郑润泽 3000 万等；`track_model.dart` `mockArtistsProfiles` (503 起) 将粉丝及专辑/作品数硬编码。画面未标为演示数据也未展示数据来源，构成用户可见的假个性化/假实时数值。
  - **优化方案**：真实数据接入并展示来源/更新时间；无法取得真实数值时删除数字与「全量真实/在听」宣称，或明确标「演示数据」。榜单更新频率须有定时刷新实现才可显示。
  - **复验**：核验各卡片/榜单/艺人/电台 API 返回值与页面逐项一致；离线/空用户下无来源的精确统计不应出现。
  - **优化方案**：让推荐卡片/画像由真实的可追溯 repository/API 驱动并呈示来源、更新时间；没有服务数据时删除播放量和「根据您常听」等个性化宣称，明确标注「示例数据」或显示空态。
  - **复验**：用两个不同的新用户/空历史冷启动并查看推荐响应；对比数据响应、歌单曲目和页面值；无来源指标必须为零呈现。
- **DATA-02｜播放队列/进度没有冷启动恢复实现；首屏显示演示队列（P1，源码已核实，UI 结果已截图）**：本轮新冷启动截图显示 6 首 mock 队列、「云水禅心」4:28、00:00。当前 `AudioPlayerService._loadFromStorage()`（`app/lib/core/audio/audio_player_service.dart:192-240`）只恢复音量、播放模式、收藏、历史与歌单；没有恢复队列或播放位置；整个生产源码也没有 `mellow_audio_play_queue` / `savePlaybackQueue` 持久化读写接口；`_playlist` 初始化仍为 `List.from(mockPresetTracks)`（同文件第 30 行），index 默认 0。旧 plist（2026-09-24 01:34:44）仍留有上一曲「告白气球 (Live)」29.929 秒与 progress=25.088 秒，但并非当前代码消费的状态。本项不描述成「两套有效状态应相等」；确定的问题是计划/规格承诺用户队列与播放进度落盘恢复，代码未实现该能力，冷启动页面使用默认 mock 曲池且无法恢复旧进度。
  - **优化方案**：增加真实播放队列与当前曲目 ID/索引/进度的版本化存储；启动时做 trackId 存在性及 duration 范围校验；无法恢复时清除失效进度并显示未播放状态，不能以默认演示曲池冒充用户队列。
  - **复验**：启动新 profile，播放/排队真实曲目 B、seek 到可确认位置、退出进程再启动；检查 UI 队列/当前曲/位置与存储一致；再删掉文件/让 URL 失效确认优雅恢复。
- **DATA-03｜收藏页把未收藏的默认曲池显示为 4 首收藏（P1，截图+落盘+源码核实）**：前台进入「我喜欢的音乐」页，截图 [`02-favorites.png`](evidence/pc-client-user-acceptance-2026-09-25-foreground/02-favorites.png) 显示「共收藏 4 首」，四首为云水禅心、海阔天空、City of Stars、起风了；本机偏好文件 `flutter.mellow_audio_favorite_ids`、`flutter.mellow_audio_favorite_tracks` 均不存在；生产 `AudioPlayerService` 初始 `_favoriteIds={'track-1','track-3','track-5','track-6'}`（`app/lib/core/audio/audio_player_service.dart:30-34`），这直接导致默认 4 首假收藏。
  - **优化方案**：初始集合为空，所有收藏显示严格由用户操作落盘的 ID 驱动；空集合应显示 0 首空状态，不用 mock favorites 补位。
  - **复验**：清洁测试账户启动→收藏 1 首→退出再启动确认仅 1 首→取消收藏后应为 0，并检查截图与 SharedPreferences ID 集合一致。
- **DATA-04｜推荐卡片播放点击未在本轮实测**：源码 `desktop_views.dart:199` 将推荐卡与内联静态曲池绑定；这一代码路径与默认 mock 曲池可静态确认，但本轮没有点击卡片，因此不把用户操作结果记为事实。
  - **优化/复验**：让推荐详情歌曲、queue drawer、dock 当前项由同一个用户可观察的播放队列状态驱动；卡片需要「加入队列/立即播放」明确分开的交互。

## 5. 执行计划/UI 原型差异核对

对照 `docs/ROADMAP.md` 桌面视图矩阵与 `docs/SPEC.md` 设计规范（它们是**预期基线，不是验收证据**）：

- ROADMAP/SPEC 描述 Modern Soft UI 桌面工作台、侧栏、多视图、队列抽屉、搜索浮层、EQ/睡眠弹层、巨幕歌词等。新截图确实显示分区侧栏、搜索入口、推荐区、队列和底栏，但本轮没有操作每个页面。
- 截图可数出 13 个侧栏入口；ROADMAP 的「12 主视图 + 4 弹窗抽屉」是视图而非导航条目计数，且包括 artist detail/fullscreen lyrics 等无单独侧栏入口的页面，当前不能仅按 13≠12 判定遗漏。下一步需逐项路由映射。
- **SPEC/ROADMAP 的数据承诺与用户可见页面不符**：首页个性化、榜单更新时间/数量、艺人真实资料、电台实时听众指标均由当前生产代码常量/mock 模型供给；前台截图与源码交叉验证见 DATA-01，而不是仅凭蓝图猜测。
- **播放队列的冷启动恢复与计划不符**（DATA-02）：SPEC 要求播放状态/队列持久化；生产代码缺少队列/进度恢复实现，首屏采用默认 mock 曲池。旧存储记录只佐证曾有播放进度，不能证明它应当对应当前首屏。

**优化方案**：追加一份版本化「原型组件/路由 ID → 生产页面/控件 → 用户动作 → 数据源 → 复验结果」矩阵；逐一覆盖桌面主视图及四种弹层/抽屉。执行计划把已实现、诚实受限、未实现、待测分开标注；为原型与生产端共用稳定 ID，避免仅对比文案或截图推断功能一致。

## 5. 本机不可验证项（不代填、不含推测结论）

| 项 | 为什么本机无法验证 | 需要什么条件 |
| :--- | :--- | :--- |
| **Windows 产物** | 本机为 macOS，无 Windows 工具链；仓库内无产物（`release_windows/` 被 gitignore） | 在 Windows 机器执行 `flutter build windows` 并实机启动，再按 44 条验收报告复验 |
| **真机听感** | 自动化只能证明「音频流真实推进 / 有真实解码时长 / `dumpsys audio` 有播放器实例」，无法证明经扬声器或耳机的听感；Android 真机取证时该机 `ringer=VIBRATE` 且静音 STREAM_MUSIC | 人工在真机用耳机试听并记录；先把铃声模式调回响铃 |
| **跨端同步互测** | 需第二台设备与可访问的真实 WebDAV / 局域网对端；单端接线与单测已完成 | 两台设备 + 真实 WebDAV 服务，做真实双向同步 |
| **系统媒体控制** | 未接入任何平台媒体控制通道，本机无实现可验证 | 明确需求后接平台通道，再在 macOS / Windows / Linux 实机验证 |
| **iOS / Linux / Flutter Web 客户端** | 本轮未构建、未验收 | 对应工具链与设备 |

> 说明：Android 真机 E2E 在上一轮尚属「本机不可验证」，本轮已由子 Agent 在 Redmi / Android 15 上完成第二轮复验（见 §1、§3.8），故不再列入本表。

## 6. 放行建议

### 6.1 对外演示（Demo）：**可以，但需规避**

可以对外演示的理由：

1. 本机四项质量基线**全部通过**（analyze / 188 单测 / macOS 构建 / 9 条桌面集成 E2E）；
2. 核心体验为**真实**：真实网络聚合、真实音频推进、真实落盘、无版权诚实提示；
3. 桌面视觉专项 **12/12 已修**，51 张真机截图可用于展示；移动端第二轮真机 6 项新修通过、无新缺陷。

演示时必须规避/如实说明：

- **不要用网易云热门曲目现场点播放**（多数 `url: null`，会走诚实提示）；优先演示 iTunes 试听、本地导入等**可播**链路。
- **不要演示 EQ 的听觉效果**（增益不作用到输出），只展示 UI 与诚实标注。
- **不要宣称跨端同步已互测通过**；只演示单端真实接线与「未发现设备」空态。
- **不要宣称 Windows / iOS 已验收**；移动端只声明 Redmi / Android 15 已复验。

### 6.2 对外发布：**不建议**

理由（均为可核对的事实）：

1. 账本总账仍有 **68 条「待修/其他」+ 1 条已确认不修 + 28 条「部分」**（未闭环合计 69 条；含移动端 9 待修、桌面端 2 待修 + 2 部分、数据真实性 19 条未回填）；
2. **核心能力承诺未闭环**：EQ 无音频链路、无系统媒体控制、无音频焦点/后台播放、可访问性为 0；
3. **未覆盖端多**：Windows 产物修复后从未复验，iOS/Linux/Flutter Web 未验收；
4. **跨端同步未互测**，无法保证双端数据一致性；
5. 项目自身定位即为「可编译、可测试、有真实播放底座与真实本地持久化的**半成品客户端，不是可发布产品**」（`README.md` / `docs/PROGRESS.md`）。

1. 回填 `ledger-mobile.md` / `ledger-data.md` / `ledger-fixplan-progress.md` 的条目状态到最新代码事实，并附证据；

5. 补 `Semantics` 可访问性并给出验收测试。

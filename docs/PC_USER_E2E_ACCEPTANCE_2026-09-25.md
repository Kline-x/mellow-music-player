## 2. 视觉验收（UI / 页面 / 布局 / 样式）

### V-1【P1】底部播放栏永久遮挡页面内容 🔴
- **现象**：所有长页面底部内容被悬浮播放栏覆盖，且**无底部安全区（bottom padding）**。发现页「热门入驻与关注歌手」整行被压住；巅峰榜「全网官方权威与特色榜单 (63)」仅露出顶部；热门歌手第三行卡片被裁；LX 音源管理第 3、4 个音源被裁；设置页「桌面歌词始终置顶 (Always on Top)」被裁。
- **证据**：01_discover、03_toplist、04_artists、11_sources、12_settings、150_default_size_discover、151_default_size_toplist、152_1024_artists；仓库自带 public/e2e_flutter_desktop_verified.png **同样存在该裁切** → 属长期结构性问题，而非本次环境差异。
- **影响**：用户永远看不到列表最后一项；1024×700 下更严重（整行被吞）。
- **优化方案**：
  1. 主内容区改 CustomScrollView + SliverPadding(bottom: kPlayerBarHeight + 16)，或给内容容器加 padding: EdgeInsets.only(bottom: 96)；
  2. 播放栏改为 Scaffold.bottomNavigationBar 参与布局（而非 Stack 覆盖），内容高度 = viewport − playerBar；
  3. 增加回归断言：滚动到 maxScrollExtent 后，最后一个 item 的 Rect.bottom ≤ 播放栏 Rect.top。

### V-2【P1】悬浮歌词胶囊遮挡页面标题与头部交互区 🔴
- **现象**：开启桌面悬浮歌词后，胶囊固定于内容区左上（约 pt 110,60 ~ 410,115），**压在页面标题、Hero 标题、歌手筛选胶囊、收藏页歌名上**。发现页 Hero 主标题被遮一半，搜索结果页标题「全网音乐搜索」被遮，热门歌手筛选行被遮。
- **证据**：130_hero_play、131_tab_playlist ~ 134_search_scrolled、146_favorites_after、152_1024_artists、153/154。
- **影响**：遮挡首屏最重要的可读信息与筛选控件；且无显式关闭按钮。
- **优化方案**：① 按 SPEC §6.2 实现为**独立、可拖动、可置顶穿透的子窗口**；② 过渡期默认位置移到播放栏上方、避开顶部 64px 安全区、胶囊 hover 显示关闭按钮；③ 明确默认关闭并给出显式开关。

### V-3【P1】EQ 弹窗预设行溢出、第 5 个预设彻底不可见 🔴
- **现象**：预设行为「原声直通 (Flat) / 澎湃低音 (Bass Boost) / 通透人声 (Clear Vocal) / 温润爵士 (Wa…」——第 4 个被弹窗右边框硬切，**SPEC 要求的第 5 个「空间 3D (Spatial)」完全不在可视区**；该行不换行、不可横向滚动。
- **证据**：31_iconA.png（全图）、eq-presets.png（2× 放大）。
- **优化方案**：预设行改 Wrap 或横向 SingleChildScrollView；弹窗宽度改为 min(920, viewport−160)；5 个预设等宽 chip + 溢出省略 + tooltip。

### V-4【P1】页面纵向严重失衡：大片空白与内容裁切并存 🟠
- **现象**：声音电台仅 4 张卡片集中左上，约 **70% 视口为空白渐变**；导入与自建歌单、播放历史、我喜欢的音乐同样下方大片空白；而发现页/榜单/歌手页内容溢出被裁。缺少统一栅格与「内容不足时的填充策略」。
- **证据**：05_radio、07_import_playlists、08_history、06_favorites vs 01/03/04。
- **优化方案**：电台页补「单集列表 / 主播卡片 / 继续收听」模块或改 2 列自适应大卡；空态统一水平垂直居中并限宽（如 720px）；为每个视图定义 min-content 与空态规范。

### V-5【P1】macOS 客户端出现 Windows 专有视觉与文案 🟠
- **现象**：本地扫描弹窗默认路径 E:\Music；设置页徽章「Windows 原生集成」「Win32 原生置顶 / 穿透」；开关「关闭主窗口时最小化至托盘」（macOS 无此链路）。
- **证据**：109_local_scan_dir、110_after_esc_filedialog、12_settings、85_gear、86_dark_mode；源码 desktop_views.dart:2553、:2590。
- **优化方案**：按 Platform.isWindows/isMacOS 条件渲染；macOS 默认路径改 ~/Music；托盘/置顶/穿透卡片在非 Windows 平台隐藏或标注「本平台暂不支持」；文案抽到平台化 i18n 资源。

### V-6【P2】顶部标题栏信息密度过高、语义重复 🟡
- **现象**：一行内塞入「品牌 + 前进/后退 + 全局搜索 + 导入歌单 + 5 色点 + 主题 + 设置」；5 个色点无文字标签，与设置页「声学柔光强调色」完全重复；⌘K 徽标暗示快捷键（实际失效）。
- **优化方案**：色点收进设置面板，标题栏只留主题切换；或色点改为带 tooltip 的可展开面板；移除失效的 ⌘K 徽标或修复快捷键后保留。

### V-7【P2】全局搜索框在不同页面表现不一致、且不可输入 🟡
- **现象**：除「全网搜索」页外，其他页面标题栏中部都有搜索框；进入「全网搜索」页后该框消失（02_search vs 01_discover）。源码显示它其实是 GestureDetector 跳转按钮（desktop_scaffold.dart:388-419），**不能真正输入**。
- **优化方案**：统一为真正的 TextField（输入即出联想下拉），或统一改为明确的「搜索」按钮，消除「看起来能打字其实只是跳转」的误导。

### V-8 正向：深浅色与 5 色强调色系统 🟢
- 深色模式、5 色强调色切换均**全局即时生效**且配色协调（按钮、胶囊、进度条、弥散光晕同步）。证据：86_dark_mode、87_accent_amber、88_accent_blue、120_dark、121_amber、122_green、123_light。

## 3. 交互验收（逐控件）

### I-1【P0】全局键盘快捷键整体失效 🔴
- **现象**（非输入框聚焦态，发现页）：Space（播放/暂停）→ 截图差异 **0.00%**（63_space_shortcut）；M（静音）→ **0.00%**（64）；L（巨幕歌词）→ **0.00%**（65）；ESC → **0.00%**（66）；⌘K（搜索）→ **0.00%**（70）。巨幕歌词页内 ESC 亦无效（41_esc1、42_esc2），L/Q/⌘K 同样无效（46/47/48/49）。
- **交叉验证**（排除注入工具嫌疑）：同一时段改用 **System Events** 的 key code 49（空格）与 key code 46（M）再测，仍 **0.00%**；而同一注入体系在 TextEdit 成功输入 hello-world-123，且在本客户端**搜索框聚焦时**可正常输入 zhoujielun（60_typed_in_search）。
- **源码对照**：快捷键映射完整存在（desktop_scaffold.dart:146-197：空格、⌘/Ctrl+K、←→±5s、↑↓音量、M、L、Q、ESC、媒体键、⌘/Ctrl+D），:177-183 明确写了「ESC 退出全屏或抽屉」。
- **判定**：绑定代码存在，但**运行时永远收不到按键**（推断为焦点树无 primaryFocus，非文本按键无法派发到 Shortcuts）。这正好解释了「打字能用、快捷键全废」。
- **影响**：README 将「全局键盘快捷键系统」列为桌面端核心能力；实测不可用，并连带造成 ESC 语义失效（见 I-2）。
- **优化方案**：① 根部包 FocusScope(autofocus: true) 或 Focus(autofocus: true) 确保恒有 primaryFocus；② 改用具名 Shortcuts + Actions，并在进入巨幕/对话框时正确转移焦点；③ 增加 sendKeyEvent(space) 后断言 isPlaying 翻转的回归测试；④ 建议再用**物理键盘**人工复验一次（本次已用两套独立注入机制否证）。

### I-2【P0】ESC 无法关闭任何模态 / 无法退出巨幕歌词 🔴
- **现象**：巨幕歌词页按 ESC 无反应（41/42），只能靠**右上角一个不带文字的圆形图标**退出（50_exited_fullscreen 成功）；该图标 tooltip 写「退出全屏 (ESC)」，与事实矛盾。本地扫描弹窗按 ESC 无效（109 → 110 弹窗仍在）；WebDAV / 导入脚本 / 导入歌单等弹窗同样只能点遮罩或「取消」。
- **优化方案**：修复 I-1 后 ESC 自然恢复；同时给巨幕歌词页加**显式返回箭头 + 文字「退出」按钮**，不依赖单一小图标。

### I-3【P2】巨幕歌词页存在死按钮 🟡
- **现象**：控制条上「歌词全屏」按钮点击无任何反应。源码 fullscreen_lyrics_view.dart:342-347 为 onTap: () {}；截图 33_iconC。
- **优化方案**：删除该按钮，或改为「歌词样式/字号」等有实际语义的功能。

### I-4【P1】搜索长列表滚轮异常、内容不可达 🟠
- **现象**：搜索 zhoujielun 返回 **96~97 条**结果，列表仅渲染首屏 8 行；滚轮下滚**最多位移一行后回弹**，连续 6 次滚动后仍停在 01–08 行；无「加载更多/分页」控件。
- **证据**：61_search_results（96 首）、157_results_top（01–07）、158_results_scrolled（02–08）、160_results_bottom（01–08）、161_scroll_step1/2/3（仍 01–08）。
- **对照**：同一滚轮注入在设置页（155→156，12.8% 位移）与结果列表首次滚动（157→158）均可生效 → **注入本身有效**。
- **优化方案**：结果列表改 ListView.builder + ScrollController 触底加载（或分页器），消除内外层滚动冲突；为 itemCount 与数据源数量加一致性测试。

### I-5【P2】标题栏前进/后退箭头无可见反馈 🟡
- **现象**：点击后退（pt≈250,27）与前进（pt≈266,27），页面差异仅 0.8%（无实际导航）。源码为真实 _history 栈（desktop_scaffold.dart:359-375），但栈为空/单条时按钮**视觉上未置灰**，用户无法判断为何点不动。证据：83_back_arrow、84_forward_arrow。
- **优化方案**：无历史时降不透明度 + not-allowed 光标 + tooltip「无可返回页面」；或单页场景直接隐藏。

### I-6【P2】播放栏右侧 6 个图标缺少 tooltip、语义相近 🟡
- **实测映射**：EQ 均衡器、⌛睡眠定时器、💬♪巨幕歌词、▭桌面悬浮歌词、♫≡待播队列、🔊静音+音量条（图标放大对照见 iconglyphs.png）。前 5 个外观相近且无 hover tooltip，新用户难以区分。
- **证据**：31_iconA(EQ)、32_iconB(睡眠)、33_iconC(巨幕歌词)、80/81(悬浮歌词/队列)、68_icon_at_1294(队列抽屉)。
- **优化方案**：统一补 tooltip；把「桌面悬浮歌词」迁出播放栏（属窗口级开关，应入设置页）；按「播放控制 / 视图控制 / 系统开关」分组并加分隔线（当前仅一段竖线）。

### I-7【P2】滚动与悬停反馈不足 🟡
- **现象**：列表行无 hover 高亮；模态出现/消失无过渡动画；深浅色切换无过渡。
- **优化方案**：补 AnimatedContainer/AnimatedSwitcher 150ms 过渡；列表行加 MouseRegion hover 态。

### I-8【P2】使用中弹出系统级媒体库授权弹窗 🟡
- **现象**：弹出 macOS 系统模态「『DSH Desktop』想访问 Apple Music、你的音乐与视频活动以及你的媒体资料库」，含不允许/允许，**阻塞整个客户端 UI**；且文案把责任进程显示为启动方（DSH Desktop）而非 Mellow Music，用户极易困惑。
- **证据**：140_playlist_cover_click、141_follow_toggle、142_all_works_tab（三张截图均可见）。
